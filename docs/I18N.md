# Многоезичност

**Езици:** английски (основен), български, испански, немски, френски, италиански.

## Как работи

| | |
|---|---|
| **Адреси** | Езикът е в адреса: `/en`, `/bg/pricing`, `/es/dashboard`… Всяка публична страница се пререндерира статично за всеки език (SEO + скорост). |
| **Първо посещение** | `src/proxy.ts` пренасочва адрес без език (`/`, `/pricing`) към най-подходящия: **1)** изричен избор (бисквитка `NEXT_LOCALE`) → **2)** езикът на браузъра (`Accept-Language`, напр. `es-MX` → `es`) → **3)** държавата от хостинга (Vercel `x-vercel-ip-country`, Cloudflare `cf-ipcountry`, Netlify `x-country`; напр. Австрия → `de`) → **4)** английски. |
| **Смяна** | Превключвателят 🌐 в хедъра и футъра запомня избора в бисквитка за 1 година и отваря същата страница на новия език. |
| **SEO** | `<html lang>` и `hreflang` връзки за всички езици + `x-default` → английски. |
| **Stripe** | Checkout и Customer Portal се отварят на езика на потребителя; текстът за автоматичното подновяване до бутона за плащане също е преведен. |
| **Цени и дати** | Форматират се по местните правила (`€1.99` на английски, `1,99 €` на немски). |

## Структура

```
src/i18n/
├─ config.ts            езици, избор на език, форматиране (дати, цени, {променливи})
├─ server.ts            getI18n() / getDictionary() — за Server Components
├─ client.tsx           I18nProvider + useI18n() — за Client Components
└─ dictionaries/
   ├─ en.ts             основен речник; задава структурата (типа Dictionary)
   ├─ bg.ts es.ts de.ts fr.ts it.ts
   └─ index.ts          зареждане при нужда
```

- **Server Component:** `const { t, href, date, price } = await getI18n();`
- **Client Component:** `const { t, href, fmt, locale } = useI18n();`
- **Server Action / Route Handler:** езикът се подава изрично (скрито поле `lang` във формите или параметър) → `loadDictionary(locale)`.
- Действията на сървъра връщат **кодове** на грешки (`invalid_credentials`, `plan_limit`…), а интерфейсът ги превежда. Така логиката не зависи от езика.
- Вътрешни линкове винаги през `href("/pricing")`, никога `"/pricing"` директно. Ако някъде се изпусне, proxy-то пак добавя езика, но с едно пренасочване повече.

## Нов текст
1. Добавете ключа в `en.ts`.
2. `npm run typecheck` показва всеки език, в който ключът липсва. Добавете превода.
3. `npm run test:i18n` проверява, че всички езици имат същите ключове и `{променливи}`.

## Нов език (напр. португалски)
1. `src/i18n/config.ts`: добавете `"pt"` в `LOCALES`, `LOCALE_NAMES`, `LOCALE_TAGS` и държавите в `COUNTRY_LOCALE` (`PT`, `BR`…).
2. Копирайте `dictionaries/en.ts` като `pt.ts`, преведете го и сменете реда на `export const pt: Dictionary = { … }`.
3. Добавете `pt` в `dictionaries/index.ts`.
4. `npm run typecheck && npm run test:i18n && npm run build`.

Stripe поддържа над 40 езика, така че Checkout ще работи автоматично. Ако езикът не се поддържа, Stripe минава на английски.

## Имейли на езика на потребителя
При регистрация езикът се записва в профила (`user_metadata.locale`). Имейл шаблоните в Supabase могат да го ползват. Виж [AUTH.md → Имейл шаблони](AUTH.md#2-имейл-шаблони--препоръчително).

## Качество на преводите
Преводите са подготвени внимателно, но не от носители на езика. Преди реклама в дадена държава е добре носител да прегледа речника, особено текстовете за абонамента, условията и поверителността.
